# 공통 회원 연결과 이전 인증 정보 정리

다붓은 회원 인증과 바이로 서비스 권한의 기준이다. 바이로 `users.userId`는 기존 네이버 계정·카페·댓글 작업·에이전트 작업의 소유 키로 유지한다. `dabutUserId`는 이 소유 키를 다붓 회원에 연결한다. 같은 로그인 이름만으로 연결하거나 소유 데이터를 옮기지 않는다.

## 연결 처리

`POST /api/auth/dabut`는 중앙에서 검증된 `ds1_` 서비스 세션을 받는다. 처음 연결하는 기존 회원은 `legacyLoginId`와 `legacyPassword`를 함께 제출해 소유를 검증한다. 성공하면 기존 `userId`에 `dabutUserId`, `authProvider: dabut`을 저장하고 로컬 `password` 필드를 제거한다. 독립 웹·데스크톱·페어링 세션은 폐기한다. 다붓 세션 메타데이터는 유지한다.

연결된 회원의 이전 로그인 및 독립 토큰 발급·검증은 차단된다. 연결 처리 중 세션 폐기가 실패하면 로그인을 완료하지 않고, 다음 연결에서 정리를 재시도한다. 회원 행과 운영 기록은 삭제하지 않는다.

## 이미 연결된 회원 정리

`MONGODB_URI`와 `MONGODB_DB`를 명시적으로 지정한다. 스크립트는 환경 파일을 자동 로드하거나 기본 데이터베이스를 선택하지 않는다.

```sh
npx tsx scripts/retire-linked-viro-credentials.ts --user-id LOCAL_OWNER --dabut-user-id CENTRAL_MEMBER
```

기본은 `dry-run`이다. 결과에는 데이터베이스 이름, 지정한 두 ID, 남은 인증 정보 여부와 세션 개수만 포함된다. 비밀번호·토큰·키 값은 출력하지 않는다. 실제 반영은 같은 명령에 `--apply`를 추가한다. 두 ID가 같은 회원을 정확히 가리키지 않거나 매핑이 중복되면 중단한다. 대상 전체 선택 옵션은 없다.

수정 대상은 `users`의 `password`/`authProvider`와 같은 소유자의 독립 `agenttokens.revoked`뿐이다. `dabut-session` 메타데이터는 보존한다. 재실행 시 이미 완료된 정리는 변경하지 않는다. `accounts`, `cafes`, 작업·발행·활동 기록, Redis 큐와 브라우저 세션 파일을 수정하지 않는다. 노출지기 프리셋은 이 명령의 대상이 아니다.

실제 실행 전 대상 ID와 dry-run 결과를 확인한다. 현재 작업에서는 실제 운영 DB 정리를 실행하지 않았다.

## 설정 접근 권한

네이버 계정 API 키 조회·변경·삭제·연결 테스트는 검증된 로그인과 `{ userId, accountId, isActive: true }` 조건을 모두 요구한다. 키 상태는 등록 여부만 반환하며, 제공업체 응답이나 오류에 포함된 키 값은 반환하지 않는다. 존재하지 않거나 타인 소유인 계정은 외부 API 요청 전에 거부한다.

전역 큐 설정은 검증된 다붓 **바이로 서비스 admin**만 조회·변경·초기화할 수 있다. 공통 member, 이전 독립 세션, 만료·폐기된 세션은 거부한다. 작업 워커의 내부 전역 설정 조회는 유지한다.
